# Mosaic Studio: Groundray engine-fit snapshot

This fictional company brain demonstrates [Groundray's first engine fit](../../docs/groundray-engine-fit.md).
It contains three root-authored knowledge drafts, generated by the existing CLI,
and 21 unchanged source captures. No human verification or actual owner approval
was recorded. The fictional business date is November 6, 2026; actual authoring
timestamps are October 12.

Start with [the navigation](knowledge/index.md), or inspect:

- [Lumen pricing and authority](knowledge/wiki/lumen-commercial.md)
- [October contribution margin](knowledge/wiki/lumen-margin.md)
- [Launch dependencies and separate Tint scope](knowledge/wiki/lumen-launch.md)
- [Original-name and source-hash receipts](source-captures.json)

Markdown originals have `.md.txt` capture names to preserve their bytes without
making them governed concepts. This is an explicit development convention, not
an automatic import feature. Open the linked captures to inspect originals.
The wiki pages use Portable KB wikilinks; `pkb get --markdown-links` can render
those page relationships as ordinary Markdown links.

This folder is a saved file snapshot within the CLI source repository, not a
standalone Git brain repository. The [reproduction harness](../../evals/groundray/engine_fit.py)
creates a separate repository, performs CLI plans/applies, installs into isolated
configs and exercises native search, source reading and explicit sync. Run it
following [the report](../../docs/groundray-engine-fit.md#reproduce), then use
`pkb brain add /path/to/generated/company` with an explicit isolated config.
Do not point `brain add` at this nested snapshot and expect it to be a Git root.

The snapshot is the second saved version, with one margin-scope clarification.
The [recorded trace](../../evals/groundray/results/2026-10-12-groundray-engine-fit-v1/trace.json)
contains the earlier body and subsequent update; the generated company repository
retains both commits. The snapshot alone does not carry its Git history.
