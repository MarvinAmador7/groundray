# Installed Groundray package trials

Groundray's development package was registered, installed and enabled through the
native Codex plugin manager. Six fresh foreground agents then explicitly used
that installed package and its frozen CLI: an author/reviewer/reader handoff and
three additional fictional company cases. This establishes an exercised local
package workflow, not automatic native activation or employee deployment readiness.

## What was installed

The frozen `0.1.0-dev.1` plugin contains Groundray's canonical 585-word Lite skill
with a package/storage bridge, a setup skill, the engine workflow/references,
a guarded helper, Apache license and the native `pkb 0.2.0` runtime. Required
source/edit/proposal commands are probed; version alone cannot distinguish this
draft engine from the older released CLI. The tested installed cache was:

`/run/codex-environment/codex-home/plugins/cache/groundray-dev/groundray/0.1.0-dev.1`

The native host was Codex `0.159.0-alpha.3`. Marketplace/plugin add and list
returned installed/enabled. Starting an ephemeral native chat hit the cloud
proxy's HTTP 403 for the Codex responses endpoint. It returned no model answer
or company actions and was interrupted; its failure events/stderr are retained.
The full native prompt was not archived. No endpoint or credential bypass was
attempted. That blocked attempt is not counted as a completed agent trial.

Foreground participants used the available chat-host runner, explicitly read the
native installed main/setup/engine skill files and ran the packaged helper.
An explicit `GROUNDRAY_PKB` override routed commands through the existing tracing
shim to the **same installed native binary**, not a mock or source-Python CLI.
The bundle checksum path was separately exercised without that override by
native installation checks and the mechanical handoff. Package snapshots and
runtime hashes are retained; the frozen plugin was unchanged during all trials.

## Additional cases

These are new companies/records with natural owner questions, one fresh reader
each. Prompts and records were frozen before dispatch. The following conclusions
are unblinded manual root assessments of actual answers and returned passages;
there is no automatic semantic correctness score.

| Case | Observed answer | Evidence and limitation |
| --- | --- | --- |
| Explicit bound and existing commitment | Preserved approved November 30 dispatch separately from conditional installation November 28–December 1. Treated nine days as the estimate's supplied bound, not a guarantee. | All three originals returned in recorded output; three valid clickable source targets. This does not test an unconditional service guarantee. |
| Compiled-only refund claim | Attributed 14,800 and alleged approval to the summary; explicitly said the original register was not inspected. Did not infer that approval never happened or authorize issuing a refund. | One owner-rule original inspected; external-register retrieval was refused as designed. Distinct fixture/catalog state tests transfer to new records, not access enforcement with two simultaneously installed companies. |

The bounded original explicitly says “between six and nine calendar days” after
a November 22 pass, and “Nine days is the upper bound of this conditional
estimate, not a service guarantee.” The dispatch addendum explicitly records
approval for dispatch by November 30 and excludes installation. Both statements
survive in the answer rather than being flattened into uncertainty or certainty.

The compiled note is the **only** supplied record containing 14,800 and the alleged
November 7 approval. Its unavailable register is declared as an external source.
The inspected owner record says “Only controller Ivo can approve customer
refunds” and “A meeting summary or a draft brain note is not approval.” There is
no alternate retained original silently supporting that amount or approval.
This assessment checks the full returned record set before identifying the gap.

Boreal's inspected originals supply 100,000 recognized assay fees, 41,000 labor
and 32,000 reagents: `(100,000 − 41,000 − 32,000) / 100,000 = 27%`.
The 9,000 depreciation exclusion is explicitly attached to contribution margin,
not every profitability measure. Director Sol's price approval covers B-9 only;
Tess's later suggestion expressly says it is not Boreal approval.

## Mechanical checks and preserved failures

A separate zero-model smoke test completes 25 operations through the bundled
helper: compatibility, three isolated setups, independent installation/selection,
source capture, knowledge creation/update, attachment, proposal, candidate review
and original inspection, explicit acceptance, sync, native index/query and
resolved source-file retrieval. Both originals retain their exact CRLF bytes.
This runs with one Git identity and records no business approval.

Five earlier mechanical attempts failed while constructing that smoke script:
incorrect positional creation arguments, missing description, unsupported JSON
selection flag, incorrect attachment arguments and mismatched file URL/path
origin. Those are harness mistakes, not model trials or silent CLI repairs.
All five raw operation logs remain beside the succeeding sixth run. The local
full-test command also initially imported the older neighboring checkout through
its editable virtual environment; its collection failure is retained. Running
with this checkout explicitly on PYTHONPATH passed **576 tests, one optional
real-QMD skip, 86.80% coverage**, plus Ruff and focused refusal tests.

Astra's requested textual review found a dangling runtime symlink fallback and
a checksum manifest that could omit the executed binary. Both were fixed before
agent dispatch. The package marker now prevents missing-runtime PATH fallback,
and the helper validates the exact binary against exactly its SHA-256 entry.
Astra's follow-up confirmed those fixes through source inspection; this is
separate from execution evidence.

Package integration CI builds the current wheel and native runtime on Ubuntu
22.04 x86_64 and macOS ARM, then runs the same mechanical handoff. Runtime/header
checks prevent cross-labeling builds. The cloud-built local bundle uses glibc
2.41 and is not evidence of older Linux compatibility; CI builds its own Linux
artifact. No models, automatic Codex activation or host-role enforcement run in CI.
All eight jobs passed on implementation commit `dc2c468` in
[run 38431443413](https://github.com/MarvinAmador7/portable-kb/actions/runs/38431443413),
including both native packages. The archive retains that implementation check.

## Interpretation and next gates

No participant was rerun, coached after dispatch, replaced, or had its output
repaired. CLI help probes are counted among command totals; complete bodies in
observer output do not prove comprehension or complete model-context exposure. Root semantic review is
unblinded. No human participants, separate-computer shared-remote handoff,
permission-denied employee roles, accuracy comparison or effort/cost advantage
are established by these six runs.

The package is a development G2 slice. Native model-backed activation remains
blocked here; clickable evidence presentation in the compiled-only answer is an
observed usability gap. Next deployment gates are successful native chat activation,
real host roles and an employee pilot that measures actual inspection and contribution.
Additional supported architectures require native build/run validation before
claiming deployment coverage. There is no release or marketplace publication.
